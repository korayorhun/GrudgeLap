# GrudgeLap in Unreal Engine 5

The Unreal Engine version of GrudgeLap: the same track and the same simulation as the Godot game, dressed with
photoscanned CC0 assets (Poly Haven) and lit by Lumen, with Nanite foliage, virtual shadow maps and a
physical sky. The simulation is not rewritten: `physics.native` builds the repository's C# physics into a
native DLL with a C interface, and the `GrudgeLapUE` module runs the game on it.

Only scripts, the C++ module and the configuration are versioned. Everything in `Content/` and `Import/` is
generated by the steps below and can be rebuilt at any time.

## Requirements

- Unreal Engine 5.8, built from source or installed. The scripts look for it in `C:\UE\5.8`; set `UE_ROOT` to
  use another one.
- Visual Studio 2022 or later with the C++ workload: the engine, the module and the NativeAOT build need it.
- .NET 8 SDK and Python 3 with `pillow` and `numpy`.
- A DX12 graphics card with Shader Model 6: Lumen and Nanite need one. On an NVIDIA RTX card the frame is
  anti-aliased and upscaled by DLSS (step 4); on any other card TSR does it.

## Building the scene

Run these from the repository root.

1. Build the simulation core. NativeAOT looks for Visual Studio with `vswhere`, so its folder must be on
   `PATH`:

   ```
   set PATH=%PATH%;C:\Program Files (x86)\Microsoft Visual Studio\Installer
   dotnet publish physics.native -c Release -r win-x64 -o artifacts/physics-native
   ```

2. Export the track from the game, once with each car. The first export gives the track and the first car
   (`track.glb`, `track.json`); the level takes only the car from the second:

   ```
   <godot> --path game -- --invisible --export-world=../unreal/Import/track.glb
   <godot> --path game -- --invisible --car=v8 --export-world=../unreal/Import/track_v8.glb
   ```

   The other cars the same way, `--car=<name>` to `track_<name>.glb`, with the names `build.cmd` loops over:
   hothatch, five, turbohatch, saloon, estate, fleet, 458, bravohgt, bravo16, leoncupra, brz.

3. Fetch the Poly Haven scans (models, ground textures, leaf and grass cut-outs):

   ```
   python unreal/Scripts/fetch_polyhaven.py unreal/Import/PolyHaven 2k
   ```

4. Add NVIDIA's DLSS plugin (optional). Download the plugin for Unreal Engine 5.8 from
   https://developer.nvidia.com/rtx/dlss (DLSS 4.5, plugin 8.9.0 when this was written; its licence is the NVIDIA
   RTX SDK EULA in the archive's `Documentation`). Copy the archive's `Plugins/DLSS` to `unreal/Plugins/DLSS`
   without `Binaries/Win64`, `Binaries/ThirdParty/WinArm64` and `Intermediate` (built for the launcher's engine;
   the runtime libraries in `Binaries/ThirdParty/Win64` stay), and its `Plugins/DLSSMoviePipelineSupport` and
   `Plugins/StreamlineNGXCommon` (which DLSS needs; `Source`, `Resources` and the `.uplugin`) beside it, and set
   `"Installed": false` in the three `.uplugin` files so the next step compiles them against this engine. The three folders are ignored by git. Without the plugin, take the `DLSS` and
   `DLSSMoviePipelineSupport` entries out of `GrudgeLapUE.uproject`.

5. Compile the C++ module. The build also copies the simulation core and the Godot version's recordings
   and grain marks (`game/assets/audio`) beside the binaries:

   ```
   %UE_ROOT%\Engine\Build\BatchFiles\Build.bat GrudgeLapUEEditor Win64 Development -Project=%CD%\unreal\GrudgeLapUE.uproject
   ```

6. Build the level, `/Game/Maps/Feasibility`:

   ```
   unreal\Scripts\build.cmd
   ```

   It runs the editor without a window and first clears the previous level, track and materials. It then
   cleans the export (`clean_glb.py`) and takes the V8 out of its own (`extract_car.py`), scatters grass,
   rocks and trees around the start and grass along every road and places the meadow camera
   (`prepare_scatter.py`), and prepares the foliage (`prepare_foliage.py`) before `build_scene.py` assembles
   the level and places the game in it. The first run of freshly built engine binaries can take half
   an hour while antivirus software scans every new DLL.

## Running it

| Command | What it does | Output |
| --- | --- | --- |
| `unreal\Scripts\drive.cmd chase 3+8+15 16` | The scripted driver takes the car round without a window; `cockpit` or `chase` view. A fourth argument plays keys instead (`2:Enter+4-20:Up+9:E`) or stays on the title screen (`title`). | Screenshots in `Saved\Screenshots\Glp`, the car's state every second in the log |
| `unreal\Scripts\render.cmd` | Movie Render Queue stills: cockpit, chase, the meadow view, the cockpit at an evening sun. | `Saved\Renders` |
| `unreal\Scripts\perf.cmd` | Frame rate of the attract-mode lap in the cockpit at 1920×1080, 900 frames; `PERF_ARGS` adds the game's switches (`set PERF_ARGS=-GlpLight=night -GlpWeather=3`). | CSV in `Saved\Profiling\CSV` |
| `python unreal/Scripts/compare.py out.jpg Cockpit godot.png unreal.png …` | Godot and Unreal pictures of the same shot side by side. | `out.jpg` |

To play, open `unreal\GrudgeLapUE.uproject` in the editor and press Play, or start the editor binary with the
project and `-game`. The keys are the Godot version's: left and right choose the car on the title screen, 1, 2 and
3 the gearbox, H the weather, L the hour (day, sunrise, dusk, night, random), Enter starts; then the arrow keys or
WASD drive, E and Q (or 1 to 7, N, R) change gear, Shift is the clutch, Space skips the replay or puts the car back on
the road, C switches the camera, U the units, F5
starts a new game, F9 the attract mode, F11 full screen and F12 takes a screenshot. A gamepad has the Godot
version's layout (left stick steers, the triggers are the pedals, RB / LB shift and pick the gearbox on the title
screen, X clutch, A starts, B skips, Y camera, Back new game, the d-pad stands in for all). At the end of a
credit that makes the top ten, the initials are entered as in the Godot version. Settings, the best lap and
the high scores (`scores.txt`, the Godot version's text form) are kept in `Saved\GrudgeLap`. Like the Godot
version, the game holds its frame rate to an even fraction of the primary display's refresh rate, at most 90 (72
on a 144 Hz panel) and 30 in the background, and logs each change (`frame cap:`): uncapped, a hybrid laptop's
GPU ran flat out and its driver timed out. Runs with `-RenderOffScreen` (the scripts below) set their own.

For automated checks, `-GlpAudioDump=<file.wav>` records the sound mix and `-GlpMute` keeps the speakers silent;
`-GlpHold` keeps the simulation from stepping (with `-GlpTitleShots` the shots' clock runs anyway), so two shots differ by
what the renderer moves alone (the wind, the clouds, the rain). `-GlpLight=day|sunrise|dusk|night|random` fixes the hour
and `-GlpWeather=0..3` the weather; `-GlpCamera=x,y,z,tx,ty,tz[,fov]` (simulation metres, a vertical field of view) and
`-GlpOrbit=yaw,pitch,distance` (on the car: 0 from behind, 90 from its right) hold the camera as the Godot version's
`--camera=` and `--orbit=` do, so the two versions can be shot alike; `-GlpNoMegaLights` keeps the night's lamps on the
classic lighting path, `-GlpStarGain=<x>` sets the stars' gain, and `-GlpRainAir=<extinction>,<anisotropy>` and
`-GlpRainGain=<x>` the night rain's air and the share of its streaks the beams light (0.77).
`drive.cmd` holds its runs to 60 fps (`t.MaxFPS`: off screen the game sets no cap of its own, and the development laptop's
GPU has dropped out under an uncapped loop), keeps the editor's on-screen notes out of the shots
(`DisableAllScreenMessages`) and passes further console commands from `GLP_EXEC` (each after a comma, e.g.
`set GLP_EXEC=,r.NGX.DLSS.Enable 0`).

The title screen offers the Godot version's line-up (`IsDrivable`: the 1970s saloon, the two Bravos and the Leon Cupra
drive in the traffic only), and the traffic is every car with a model in turn, in the road's twelve colours, as the Godot
version's since 0.70 (the Ferraris keep their red). Each car keeps its own best lap (`best_lap_<car>.bin`). The instant
replay plays the player's own tune: `replay.wav` or `replay.ogg` from this version's music folder or the Godot
version's (which keeps the tune it is given as `replay.ogg`), decoded by the engine's Vorbis decoder, else the game's own.

**Hardware ray tracing (0.74).** `r.RayTracing` is on: Lumen traces the scene's geometry instead of its distance
fields, and reflections are lit where the ray lands (`r.Lumen.HardwareRayTracing.LightingMode` 2), so the paint, the glass
and the wet road mirror their surroundings. The grass tufts and the bushes stay out of the ray-tracing scene (a quarter of
a million instances; Lumen warns above 100 000). A card without ray tracing keeps software Lumen. On an RTX card with the
DLSS plugin the game also turns on **DLSS Ray Reconstruction** (`AGlpGame::EnableRayReconstruction`, through the plugin's
`UDLSSLibrary`): one trained denoiser takes the place of Lumen's reflection denoisers and the shadow denoiser; the log says
`DLSS Ray Reconstruction: on`, and `-GlpNoRR` keeps the built-in denoisers for a comparison.

On an RTX card with the plugin (step 4) DLSS takes TSR's place (`r.NGX.DLSS.Enable` in `Config/DefaultEngine.ini`) in its Quality mode: the frame is rendered at a fixed 75 % of the window and upscaled. Dynamic resolution is off: the plugin picks its mode by the top of the dynamic range and took DLAA, which takes 99 to 100 % only, and the packaged game stopped on DLSS's assertion the first time a frame was rendered below that. The log says `LogDLSS: NVIDIA NGX DLSS supported 1`; `-ExecCmds="r.NGX.DLSS.Enable 0"` puts TSR back for a comparison.

**Times of day and the night (0.77).** The Godot version's four hours, by the numbers it stores them (`light=` in
`settings.ini`: 0 day, 1 sunrise, 2 random, 3 night, 4 dusk): **L** on the title screen steps day, sunrise, dusk, night
and random (a draw for every credit), as **H** steps the weather (H and M were missing from the keys the game reads, so
until 0.77 they only ever worked from a script). Without a choice the day is the level's own, value for value. The
hour's numbers are one table, `GlpLookFor` in `Source/GrudgeLapUE/GlpLook.h`, applied with the weather by
`AGlpGame::ApplyWeather`:

- **Sun and moon:** the level's one directional light, the sky atmosphere's sun, turned to the Godot version's
  `SunriseDirection` (5.85° up), `DuskDirection` (behind the Tetons, the circuit in their shadow) or `MoonDirection` (17°
  up). The sun keeps its 75 000 lux at every hour: the atmosphere reddens and dims a low sun by itself, which the Godot
  version's hand-picked sunrise and dusk colours stood in for. The moon gives 0.9 lux on the ground (the light's own
  value is what the atmosphere needs for that: `GetAtmosphericLightToMatchIlluminanceOnGround`) in Godot's bluish
  `MoonLight`; the sky draws its disc. The night's sky and aerial perspective are at 0.6, so the far mountains are not
  veiled in pale blue. Under cloud the light comes from the day's direction without a disc (Godot's rule), at 1800 lux
  at sunrise, 900 at dusk and 0.6 on the ground at night.
- **Exposure** (fixed, EV100): day 14, sunrise 12, dusk 10.6, night 1; grey 11.6, 9.9, 10.2 and 1, rain 11.2, 9.6, 10.0
  and 1, so the grey sunrise's picture is 0.9 stops under the grey day's and the grey dusk's 3.1, as Godot's are (worked
  out from Godot's light and exposure numbers, 0.4 and 1.4, they came out a stop too bright). Bloom and grain step down
  at dusk and at night, the lens flare at sunrise and dusk too (0.04 against the day's 0.12: the low sun dead ahead threw
  a green ghost and a blue disc across the road and the windscreen). Measured on the start-line view against the Godot
  version (`-GlpCamera=-10,1.6,0,200,8,0,50`, both versions), in stops over Godot's for the sky, the mountains and the
  plain: the day (as in 0.76) +0.4, +0.8, +0.1; sunrise +0.2, +0.3, +0.8; dusk +0.3, +0.2, −0.2; night +0.1, +0.7,
  +1.0; under grey and rain every hour keeps the grey or the rainy day's own differences (−0.9, −0.4, −0.3 and +0.5,
  +0.9, +0.2) to within 0.4. The first estimates, EV 10.5 and 9.5 and a 1 lux moon at EV 0, came out two to three stops
  too bright.
- **Clouds:** the template's `Cloud_GlobalCoverage` is an offset on its noise (the level's −0.2, the overcast's 0.95),
  so a clear sunrise, dusk and night take the Godot version's steps from its day: −0.19, −0.09, −0.11. The game keeps
  one dynamic instance of the cloud material for every other sky and puts the level's cloud layer back for a clear
  credit (until 0.77 a clear credit after a grey one kept the overcast's lower, thicker layer).
- **Stars** (`M_NightStars`, `STARS_HLSL`): on a clear night a post-process material adds about 9 200 procedural stars to
  the sky's pixels after the upscaler (the Yale catalogue's count to magnitude 6.5, each a gaussian a pixel and a half
  wide holding all of its light, dimmed by the air mass, none on the land, fading where the sky is brighter than a clear
  night's: the clouds, the moon's glow), at ten times the catalogue's brightness, as the night's exposure is set for the
  lamps. A sky dome did not work in this engine: an Is Sky mesh never showed over the sky (the atmosphere drew its own
  sky over it), and a plain dome was not drawn past 15 to 30 km.
- **Lamps**, dusk to dawn (the cars' glows and tail lamps also in the rain, as Godot's `CarLampsLit`):
  - the low beam is an IES light profile (`IES_LowBeam`, written by `write_low_beam_ies` from `LOW_BEAM`): a flat
    cut-off 0.57° down on the oncoming side stepping up 15° over the verge, 20 000 cd at the hot spot, the foreground
    kept down (about 940 cd 7° down), the ECE R112 class B points checked;
  - each car's lamp sockets sit on its own lamps' lenses (`prepare_model_car.py lamp_sockets`; tags `GLP.LampHeadL` … in
    `rig_car`): the front `GLP_Lens`, a cluster at a headlamp's height before a fog lamp under it; the red of the rear
    `GLP_Brake` (a textured lens's amber and white parts left out), else the rear lenses; or the materials `LAMP_MATERIALS`
    names for a model (the BRZ's LED projectors, the estate's `Phare_avt`, the saloon's tail lamps). The socket is on the
    lens under its cluster's middle: the first ones, at the middle's height but the lens's tip, hung up to 23 cm in the
    air in front of a swept lamp. The 205's lamps, regions of its body's texture, and the saloon's outer round headlamps
    are measured (`MEASURED_LAMPS`); the Godot version's box rule, its width now taken at the car's ends without the side
    mirrors, is left for a model without any;
  - the player's car: two beams 8 cm ahead of the body, their shadows from the virtual shadow maps (traced against the
    ray-tracing scene's coarser stand-in of the car's own nose, every shadow ray was blocked and the road went dark 7 m
    out), and the tail lamps' red on the road behind (3 cd, 12 braking); each drone one beam between its lamps, without
    shadows, as in Godot; the train's lamp and its coaches' lit windows (`M_TrainWindow`); the seven farms' sodium yard
    lamps on the export's poles (`GLP.YardLamp`, 750 cd straight down);
  - every lit lamp shows its glow (`M_LampGlow`, the Godot version's `lamp_glow.gdshader` in real units): a card turned to
    the camera carrying the lamp's luminance, never under a pixel and a half wide, seen from each side as its pattern
    sends the light, held under the half floats' range; the brake lamps' lenses glow at a tail lamp's level while lit and
    flare with the brake, each as its part of the car (`prepare_model_car.py brake_parts`, `BRAKE_LAMP_HLSL`): a centre
    high-mounted stop lamp (the Clio's, the 458's) with the brake alone, a front marker made of the same material (the
    V8's, the five's indicators) never, and a textured lens (the estate's, the five's) only in its red;
  - the marker posts' reflectors (`M_Reflector`, 500 cd per lux per m²) and the road paint's glass beads (`M_RoadPaint`,
    0.15) send the player's beams back (`MPC_Night`, written every frame): bright ahead, fading close up as real ones do.
  - **Rain at night:** the beams stay out of the translucency lighting volume (its cells are a metre or two across, and a
    20 kcd lamp in one lit the rain's streaks and the wheels' spray white all round the car), so `M_Rain` lights each
    streak from the player's two beams itself (`RAIN_BEAMS_HLSL` on `MPC_Night`, as the retroreflectors: the beam's
    pattern over the distance squared, a drop sending a share of it back towards the lamps and more on along the beam,
    `RainGain` 0.05 for the part of its streak a real drop fills). The height fog's volumetric fog carries the beams' glow
    in the air: twice the rain's density, scattering about evenly (anisotropy 0.2, the Godot version's; at 0.7 the light
    went on along the beams and almost none came back to the seat), from 2.5 m out and in over 1.5 m (nearer, its cells
    lit the cabin through the car). Its cost is in the frame times below.
- **MegaLights** is on in the post-process volume while the lamps are lit and hardware ray tracing is available: about
  twenty lights at a flat cost, the yards' with ray-traced shadows. Without it, or with `-GlpNoMegaLights`, the lamps take
  the classic path and only the player's two beams cast shadows, as in Godot.
- **Shadows' cache:** a virtual shadow map keeps a page until something in it moves, and a page drawn while Nanite was
  still streaming a mesh in kept that mesh's coarse shadow: in 0.76's level too, and in every 0.77 build, a shadow some
  20 m across lay over the road and the verges at the start line with nothing to cast it (gone with
  `r.Shadow.Virtual.Cache 0`). `r.Nanite.VSMInvalidateOnLODDelta=1` (`Config/DefaultEngine.ini`) has the clusters that
  stream in invalidate the pages they were drawn into; it costs nothing measurable on `perf.cmd`'s lap.

Frame times (`perf.cmd` with `PERF_ARGS`: the hot hatch's attract lap in the cockpit, 1920×1080, DLSS Quality, hardware
ray tracing, RTX 5060 Laptop; milliseconds, median and 95th percentile; the frame is held by the render thread):

| Cell | Frame | Render thread | GPU |
| --- | --- | --- | --- |
| clear day (`-GlpLight=day`; 0.76: 16.45) | 16.4 to 16.9, p95 20.4 to 21.6 | 16.4 to 16.9 | 15.5 to 16.0 |
| clear dusk | 17.2, p95 21.1 | 17.2 | 16.3 |
| clear night, MegaLights | 17.6 to 18.1, p95 23.0 to 24.4 | 17.7 to 18.1 | 16.7 to 17.1 |
| clear night, `-GlpNoMegaLights` | 17.1 to 17.4, p95 22.5 to 22.6 | 17.1 to 17.3 | 16.3 |
| night rain | 17.9 to 18.2, p95 23.0 to 23.8 | 17.9 to 18.2 | 17.1 to 17.2 |
| day rain | 16.4 to 16.5, p95 20.0 to 21.3 | 16.5 | 15.3 to 15.5 |

With twenty-odd lights the classic path is still 0.5 to 0.7 ms cheaper than MegaLights' flat cost; MegaLights buys the
yards' shadows and room for more lamps. The night rain costs 1.4 to 1.8 ms over the day rain (p95 1.7 to 2.5): the
night's lamps as on a clear night (MegaLights 0.9 ms of GPU, the beams' virtual shadow maps 0.4) and the volumetric
fog, 0.6 ms of GPU plus 0.1 in MegaLights' volume. With the fog's grid at 16 pixels (`r.VolumetricFog.GridPixelSize`,
8 by default) it took 0.3 ms, but the frame, held by the render thread, was no shorter (18.4 ms), so the grid stays.

Not yet as in Godot: the clouds at dusk are white where Godot's are pink, the moonlit plain is a stop brighter than
Godot's (both all but black), the signs are not retroreflective, and in the rain at night the streaks catch the player's
beams and the yards' lamps (through the translucency volume) but not the oncoming drones' beams, which stay out of that
volume as the player's do.
The dusk's afterglow stands over the sun, right of the start straight (bearing 285, Godot's `DuskDirection`), where
Godot's sky photo glows left of it; looking into it, the meadow's rocks shine white (their 0.76 material's specular, kept
as the day has it). The train's lamp is where Godot's is, at the locomotive's cowcatcher, but in both versions the
locomotive runs cab first and the lamp faces back over the first coach (the model's turn in the export and TrainView, a
Godot-side change). The lightning's and the windscreen's hour values wait for a storm and a windscreen of their own, and
the night's sounds for an ambience in `GlpAudio`.


## Packaging

A stand-alone build (`GrudgeLapUE.exe` with the cooked level, the simulation core and the recordings beside it):

```
%UE_ROOT%\Engine\Build\BatchFiles\RunUAT.bat BuildCookRun -project=%CD%\unreal\GrudgeLapUE.uproject -noP4 -platform=Win64 -clientconfig=Development -build -cook -stage -pak -archive -archivedirectory=<folder> -unattended -nocompileeditor
```

With an engine built from source, the first run compiles the whole engine for the game target (over an hour on
the development laptop); later runs only cook what changed (five minutes). The release's preview
(`GrudgeLapUE-Preview-<version>.zip`, since 0.44) is the archive's `Windows` folder without the debug symbols
(`GrudgeLapUE.pdb`, 2.6 GB) or a `Saved` folder, with the repository's `THIRD_PARTY.md` and the car models'
credits (`Import/Models/LICENSE.txt`) beside the executable.

## How the pieces fit

- `Source/GrudgeLapUE/GlpLibrary.*` loads `GrudgeLap.Physics.Native.dll` and checks its ABI version.
- `GlpGame.*` is the game, as `Bootstrap.cs` runs it in Godot: it steps a session every frame with the keyboard
  (`GlpInput`, the Godot version's ramps and keys) or the attract-mode driver, and moves the cars (`GlpCarView`:
  the imported car's wheels, suspension and steering wheel, and copies of its exterior for the traffic and the
  ghost), the train and the signs that tip over. The camera follows with the game's cockpit, chase and replay
  placements (`GlpCamera`).
- `GlpScores.*` is the high-score table and the entry of initials, as `HighScoreTable.cs` and `ScoreBoard.cs`
  keep them in Godot, in the same text form.
- `GlpHud` draws the readouts, the title screen and the high-score panel on the canvas; `GlpInstruments` draws the instrument panel
  into a texture shown on the binnacle and at the foot of the screen; a scene capture fills the rear-view
  mirror. `GlpAudio` mixes the recordings and the synthesis the way the Godot version does, at 44.1 kHz; the
  engine voice is the simulation core's (`glp_engine_*`, the same `audio/GranularEngine` Godot plays, with the
  overrun recordings off the throttle), rendered on the audio thread, and the cabinet's chime, starter and
  jingles (the fanfare of a record lap, the tune of the credit's end) are the same note tables as Godot's.
  The crash recordings, the shifter's clunk and the train's steam loop are mixed in too, the steam by the
  train's distance; the Godot version's placed drone engines and Doppler shift are not (the mix is mono).
- **Coordinates:** the simulation's (x, y, z) in metres is (x, −z, y) × 100 cm in Unreal. Godot shows it as
  (x, y, −z), and the glTF import maps Godot's (x, y, z) to Unreal's (x, z, y).
- `Scripts/build_scene.py` writes the level and tags what the game moves. It holds the record of what the
  export needed:
  - **Required extension:** the export marks `KHR_node_visibility` as required, and Unreal rejects the file.
  - **Wound primitives:** some are wound against their normals, and the terrain disappeared.
  - **Vertex colours:** Interchange leaves them out of glTF materials, and the red car turned white; Unreal
    also hands materials the sRGB-encoded bytes, which paled every colour until they were decoded.
  - **Foliage cut-outs:** the alpha comes in separate maps.
  - **Leaf thinning:** Nanite thinned the leaves until the trees went bare.
  - **Screens:** the instrument panel and the ghost glow in the screen's light units (the level's exposure is
    fixed for sunlight); the mirror shows the scene's light before exposure, so it matches the view ahead.
  - **Cabin photos:** Godot lays the leather, fabric and carpet on with triplanar mapping, so those meshes come
    without texture coordinates; a material projects the photos in each part's own space instead.
  - **Plain paint:** the strakes and trims carry their own paint material; it takes the traffic's colours too.
  - **The wood:** the export's `forest` placements become instanced scanned trees (`Wood*`, drawn to 2.5 km);
    the one-of-each template meshes the file carries (`ForestVariant-<n>`) are removed from the level.
  - **The road's wear (0.13):** the asphalt scan is sampled a second time, a quarter turn round and 0.71 times
    the size, and blended in by a slow noise, with a 57 m brightness wobble on top, so the tile never reads as a
    repeat along a straight; the game's wear sheet runs 160 m; and `road_decals` scatters 300-odd deferred decals
    along the exported centrelines (`roads` in track.json, every 8 m): cracks, patches of other asphalt, oil in the
    wheel tracks, skid marks and the odd pothole, drawn by `make_decals.py` from no source material.
  - **The weather (0.13):** `MPC_Weather` (Wetness, Rain) is read by the ground materials: a wet road darkens,
    its roughness drops to a sheen with mirror-flat standing water where a world-aligned puddle mask is high, and
    the verge and the grass darken and dull. The game sets it from the simulation's weather (`glp_state.weather`,
    drawn for every credit; `-GlpWeather=0..3` fixes it: dry, overcast, wet, rain), and under any weather but a
    clear day drops the sun to a wide soft source, closes the clouds over (the template cloud material's coverage
    parameter), thickens the fog and opens the exposure (`AGlpGame::ApplyWeather`). Rain (0.76) is the Godot version's
    3600 thin lit streaks (`M_Rain`) falling through a box 10 m over the eye and 5 m ahead, led by where the camera will be
    when they reach it, gone within 1.2 m of the eye (`AGlpGame::FallRain`); until 0.76 a panning sheet on a cylinder.
  - **The roadside (0.76):** the export carries the fences, the power poles and the marker posts as placements of one
    template mesh each (`instanced` in track.json, `Instanced-<n>` in the file; `WorldExport`), which `place_instanced`
    instances with the template's mesh and material: about 3000 buck-and-rail bays, 76 poles with the three wires strung
    between neighbours as the game's 0.9 m sag parabolas (one-metre pieces of `Instanced-Wire`), 158 posts with their
    reflectors amber on the right and white on the left. Until then the export left the fences and the line out and sent
    the posts as grass tufts.
  - **The plain (0.76):** the ground's colour varies on three scales as the Godot ground's (dry straw stretches, greener
    hollows, half-metre clumps; `GROUND_HUES_HLSL`), and sagebrush, the scanned shrubs small and tinted grey-green, stands
    6 to 120 m off every road (`prepare_scatter.sagebrush`, about 47 000). The scatter is in hierarchical instances.
  - **Brake lamps and tyre marks (0.76):** a model's `GLP_Brake` lens becomes `M_BrakeLamp`, lit while the car brakes
    (`FGlpCarView::SetBraking`: the player's pedal; a drone slowing faster than 1.2 m/s² for 0.4 s); a sliding wheel lays
    a strip of `M_SkidMark` (modulating, so it darkens the road beneath) from 0.32 of its slip intensity, as the Godot
    version's `SkidMarks` (`AGlpGame::LaySkidMarks`, 6000 strips in a ring).
  - **Dust, smoke and spray (0.76):** the Godot version's `WheelDust`: dust off the verge and the plain, the pale smoke of a
    sliding tyre, the spray of a wet road behind the player's wheels and the traffic's, as a ring of camera-facing
    instances (`AGlpGame::ThrowPuffs`, `M_Puff`). `-GlpPuffTest` throws all three from every wheel.
  - **The wind (0.76):** the grass, the sagebrush, the bushes and the trees lean and sway in the Godot version's wind
    (`WIND_HLSL`, a world position offset on windy copies of the scanned materials, `wind_on_plants`), within 30 to 150 m.
  - **The glass (0.76):** a model's window drawn as two parallel layers keeps its outer one (`prepare_model_car.py`).
  - **The camera (0.76):** the seat's smooth 11 Hz vibration, a knock's jolt, the chase eye following the loop
    (`GlpCamera`, as the Godot version's `CameraRig`).
  - **The photographic finish (0.13):** a little film grain, a trace of chromatic aberration and lens flare, a
    touch more bloom and motion blur in the post-process volume; the chase camera a 54 degree lens from 7.4 m, as
    the Godot version's since 0.11.

## Real car models (0.74: the Godot version's own, cabins included)

Since 0.74 every car with a prepared model in the Godot version (`game/assets/models/<key>.glb`, written by
`tools/prepare_car_models.py`) is drawn here from that very file, cabin and all (`Scripts/prepare_model_car.py`, run by
`build.cmd` after the older step below): the export's lofted car under `PlayerCar` goes, and the model comes in as
`ModelBody` (its body and cabin, tagged `GLP.Exterior` and seen from the seat too), `Wheel0..3` with a `Spin` each,
`Steering/Spin`, the driver's `Eye` (the cockpit camera's place, `GLP.Eye`), `Dials` (a quad the size the prepared node
gives, on which the game shows its instrument panel) and `RearMirror` (its glass, `MirrorGlass`, sized by the prepared
node; a housing and a stalk where the game hangs its own). Nodes no scene reaches are pruned from the file: left in, the
importer gave the model's `Wheel0`, `Spin` and `Dials` a unique suffix because the lofted car's nodes had the same names,
and the level found no wheels. The model's `GLP_Paint` becomes a clear-coated paint in the model's own colour
(`M_CarPaintSolid`) or over its texture (`M_CarPaintTextured`, the converter names them `GLP_PaintFlat` and
`GLP_PaintTex`), `GLP_Glass` and `GLP_Lens` the clear glass; a mesh with a translucent slot is built without Nanite. So
the Unreal cockpit is the Godot cockpit, and the cars' credits are the Godot version's (`THIRD_PARTY.md`, copied into the
preview with `CREDITS-car-models.txt`).

### The older step (0.13)

The lofted bodies the game exports are stand-ins; the level puts real car models in their place
(`Scripts/prepare_car_model.py`, driven by `Import/Models/models.json`): the model is turned to face the car's
way, scaled so that its wheelbase is the simulation's, set down with its hubs at the rest hub height, its body
hung under a `ModelShell` node in place of the lofted shell, bonnet, glass and outside details, and its wheels
re-centred on their hubs under the game's own `Spin` pivots, so they steer and roll with the simulation. The
game's cabin (dashboard, dials, steering wheel, mirror) stays; a model's own interior is left out. The glass is
found by name or by a translucent material and given the clear glass. `fetch_models.py` downloads the models
(not versioned, 14-37 MB each) from the Objaverse mirror on Hugging Face; each is CC BY 4.0, with its author,
source and the credit line the licence asks for in the `LICENSE.txt` beside `models.json`:
